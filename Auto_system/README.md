# Team 14 Robot Challenge - Auto System

This repository contains the competition firmware for Team 14's robot, targeting the **Arduino Giga R1 WiFi**. The current main program uses a simple sequential control flow in `src/system.cpp`. The previous FSM implementation has been removed from the active firmware path.

## What The Firmware Does

The main control logic runs on the Giga M7 core and drives the full competition sequence:

1. Wait for safety conditions and a start command.
2. Request exit airlock B.
3. Follow the line toward the exit door.
4. Use Lidar to detect the door area and confirm that the door is open.
5. Drive through the tunnel into the main arena.
6. Follow the arena line while avoiding close obstacles.
7. Read RFID tags and ask the server whether the soil is fertile.
8. Align, open the hopper, drop a seed, and report the planted seed.
9. Return to base after planting 5 seeds or reaching the arena time limit.
10. Request entry airlock A, drive through the tunnel, stop in base, and report mission completion.

All robot movement is protected by the safety gate:

- Motor controller initialization must succeed.
- The kill switch must be safe.
- The robot must receive `type=heartbeat enable=1`.
- The heartbeat must not be timed out.

If any condition fails, the robot immediately calls `stop_all()`.

## Safety Logic

Every `systemLoop()` iteration runs this order:

1. Poll WiFi/MQTT.
2. Check serial commands.
3. Send the periodic register message.
4. Update kill switch, revive button, and Lidar readings.
5. Check the safety gate.

When safety is blocked:

```text
robot.stop_all()
LED shows emergency
send status
return
```

The safety gate is controlled by `safetyAllowed()`:

- `motorReady == true`
- `killSwitch.isSafe() == true`
- `type=heartbeat enable=1`
- heartbeat age is less than `WIFI_HEARTBEAT_TIMEOUT_MS`

## MQTT Messages

Configuration is in `include/WiFiHandlerConfig.h`:

- `WIFI_SSID`
- `WIFI_PASSWORD`
- `BROKER_HOST`
- `BROKER_PORT`
- `GROUP_ID`
- `BOARD_ID`
- `SERVER_BOARD_ID`
- `WIFI_REGISTER_INTERVAL_MS`
- `WIFI_HEARTBEAT_TIMEOUT_MS`

Security note: WiFi credentials are currently stored in plain text. Remove or replace them before publishing the repository.

## Serial Test Commands

Serial baud rate: `115200`

```text
S  start the competition flow
R  request return to base
X  disable remote safety and stop immediately
```

Even after sending `S`, the robot will not move until the heartbeat safety gate is valid.

## Testing Notes

Before powered movement tests:

1. Lift the robot or remove the wheels.
2. Confirm that the kill switch stops motion.
3. Run `pio run`.
4. Upload the firmware and open the serial monitor.
5. Confirm that `Simple competition system ready.` is printed.
6. Confirm that the server is sending `type=heartbeat enable=1`.
7. Start with serial `S` or MQTT `type=start`.

```text

test/servo_test.cpp

```

## Current Design Choices

This version is intentionally simple:

- No old FSM implementation is used.
- No complex navigation map is implemented.
- Arena movement uses the existing IR line follower and Lidar obstacle check.
- RFID fertility and planted status are decided by the server.
- Planting uses fixed timing and a servo-controlled hopper.
- The M4 core currently runs an empty stub; the main logic is on M7.

For more precise competition behavior, extend `src/system.cpp` by adding state-specific logic to the existing `RunState` flow.
