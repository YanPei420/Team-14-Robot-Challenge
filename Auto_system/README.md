# Team 14 Robot Challenge - Auto System

This repository contains Team 14's robot firmware for the **Arduino Giga R1 WiFi** using PlatformIO and the Arduino framework.

## Assessment Version

The code to upload for the viva/test run is the active `src/main.cpp` entrypoint:

```cpp
#include "system.h"

void setup() { systemSetup(); }
void loop() { systemLoop(); }
```

`src/main.cpp` delegates to the full autonomous challenge system in `src/system.cpp` / `src/system.h`.

Assessment evidence is kept in:

- Software overview diagram: `docs/software_overview.md`
- Behaviour flowcharts: `docs/system_flowchart.md`
- Testing and calibration evidence: `docs/testing_calibration.md`
- Motor wiring notes: `lib/01 MotoronDrive/WIRING.md`
- Motor module notes: `lib/01 MotoronDrive/README.md`

## Competition System Overview

`src/system.cpp` contains the full autonomous challenge flow for the Giga M7 core. It initializes:

- Motoron drive and encoder speed control
- IR line sensors
- three Lidar sensors
- RFID reader
- kill switch
- revive button
- status LED
- MQTT messenger
- planter mechanism
- line follower and wall follower helpers

The component interaction diagram is in `docs/software_overview.md`.

The M4 build currently uses the stub branch in `system.cpp` and only delays in `systemLoop()`.

The competition system uses this `RunState` enum:

```text

EntryTraverseTunnel

PlanterTest

```

Typical autonomous path:

```text
Idle
  -> ExitLineToDoor
  -> ExitRequest
  -> ExitWaitDoor
  -> ExitTraverseTunnel
  -> GridDrive
  -> SoilQuery
  -> AlignSearch
  -> FineAdjust
  -> PlantOpen
  -> PlantVerify
  -> GridDrive
  -> ReturnToAirlock
  -> EntryRequest
  -> EntryWaitDoor
  -> EntryTraverseTunnel
  -> InsideBase
```

The system follows the line to the exit airlock, requests airlock B, wall-follows through the tunnel, drives the arena line, queries RFID soil data, plants up to 5 seeds, returns to airlock A, and reports mission completion.

Detailed Mermaid flowcharts for the runtime loop, safety gate, state transitions, inputs, and server outputs are in `docs/system_flowchart.md`.

## Safety Logic

Autonomous movement is allowed only when all safety conditions pass:

- Motor controller initialization succeeded.
- Kill switch is safe.
- `type=heartbeat enable=1` has been received.
- The heartbeat has not timed out.

If autonomous and local-control safety are both blocked, `systemLoop()` stops the robot, updates the LED, sends status, and returns.

Manual control and planter test mode are treated as local-control modes, but they still require the kill switch to be safe.

### Messages Sent By The Robot

```text
type=register team_id=14 board_id=Robot14
type=status team_id=14 board_id=Robot14 state=<state> seeds=<n> safety=<0|1>
type=openAirlockB team_id=14 board_id=Robot14
type=openAirlockA team_id=14 board_id=Robot14
type=isFertile team_id=14 board_id=Robot14 tag_id=<uid>
type=seedPlanted team_id=14 board_id=Robot14 tag_id=<uid> count=<n>
type=missionComplete team_id=14 board_id=Robot14 seeds=<n>
```

### Messages Received By The Robot

```text
type=heartbeat enable=1
type=heartbeat enable=0
type=start
type=stop
type=emergency
type=disable
type=openAirlockReply accepted=true airlock=A
type=openAirlockReply accepted=true airlock=B
type=isFertileReply tag_id=<uid> x=<n> y=<n> fertile=<true|false> planted=<true|false> blocked=<true|false>
type=rfid tag_id=<uid> x=<n> y=<n> fertile=<true|false> planted=<true|false> blocked=<true|false>
type=return
type=emergency_warning
type=stranded
type=revive
type=base_reached
```

RFID replies can update the internal 9 x 9 arena grid. Only the lower line-following rows are currently routeable.

## Serial Commands In `system.cpp`

Serial baud rate: `115200`

```text
S          start autonomous mission
R          request return to base
X          disable remote safety and stop
M          enter manual control
P          leave manual control and stop in Idle
W/B/A/D    manual forward/back/left/right
Q/E        manual rotate left/right
L          manual line follow
G          manual wall follow
O/C/T      run planter 180-degree cycle
0 or Space manual stop
+ / -      manual speed up/down
?          print help
```

In manual mode, `S` is interpreted as backward movement so the familiar `W/A/S/D` layout works.

## Testing Notes

Before powered movement tests:

1. Lift the robot or remove the wheels.
2. Confirm that the kill switch stops motion.
3. Run `pio run`.
4. Upload only the intended entrypoint.
5. Open the serial monitor at `115200`.
6. For autonomous mode, confirm the server is sending `type=heartbeat enable=1`.
7. Start autonomous mode with serial `S` or MQTT `type=start`.

Module tests are available in `test/`, including:

```text
test/Motor_run.cpp
test/line_follow.cpp
test/wall_follow.cpp
test/Lidar_test.cpp
test/RFID_test.cpp
test/servo_test.cpp
test/encoder_test.cpp
test/wifi.cpp
```

`test/line_follow.cpp` supports real-time serial PD tuning while the follower
runs:

```text
kp=0.08
kd=0.004
pd 0.07 0.004
show
help
```

Commands are applied when the serial monitor sends a newline. A leading `!`
is also accepted, for example `!kp=0.08`.

Debugging tools are available in `tool/`, including the navigation visualizer.

The viva evidence log, calibration values, current limitations, and final-day checklist are in `docs/testing_calibration.md`.
